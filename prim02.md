# Французский перевод с артиклями и последующим озвучиванием

## Статус реализации

Первый экспериментальный этап реализован локально:

- добавлен отдельный `FrenchGrammarProcessor`;
- в Setting доступны автоматический, определённый, неопределённый и
  отключённый режимы;
- внешний словарь создаётся как `language_data/French/lexicon.json`;
- правила применяются к обычному и пакетному переводу, Ctrl+Space,
  «Озвучить» и «Повторить» до построения IPA и вызова TTS;
- неизвестные слова и полноценные предложения остаются без изменений;
- обработка покрыта автоматическими тестами.
- тестовый файл `набор-франс.txt` связан с 20 детерминированными словарными
  соответствиями и проверяется во всех активных режимах артиклей.

На этом этапе используется консервативный встроенный и пользовательский
словарь. Подключение статистической модели spaCy оставлено следующим этапом,
чтобы не добавлять тяжёлую зависимость и не применять предположения о роде с
низкой уверенностью.

## Цель

Добавить для языкового модуля French управляемую грамматическую обработку,
которая корректно дополняет отдельные французские существительные и именные
группы артиклями, а затем использует окончательный вариант текста для
транскрипции IPA, озвучивания и экспорта.

Артикль нельзя добавлять механически ко всем результатам перевода. Он зависит
от значения исходного текста, рода, числа, определённости и фонетических
особенностей французского существительного.

## Уточнение примеров

Форма `la tableau` грамматически неверна:

- предмет мебели «стол» — `la table` или учебная форма `une table`;
- картина, доска или таблица — `le tableau` или `un tableau`;
- столы — `les tables`;
- школа — `l’école`, но учебная форма `une école` лучше показывает женский род;
- герой — `le héros`, поскольку начальная `h` в этом слове не допускает
  элизию.

Для полноценного предложения артикль должен определяться переводчиком в
контексте:

- `Это стол.` → `C’est une table.`;
- `Я вижу стол.` → `Je vois une table.`.

Такие предложения не следует повторно изменять постобработкой.

## Рекомендуемая архитектура

Следует создать отдельный класс `FrenchGrammarProcessor`, не связанный с GUI и
общим сетевым сервисом перевода. Обработчик получает исходный текст и готовый
французский перевод, после чего возвращает окончательный текст и сведения о
применённом правиле.

Общая цепочка обработки:

```text
исходный текст
    → перевод
    → французская грамматическая обработка
    → транскрипция IPA
    → TTS
    → сохранение TXT/MP3
```

Эта цепочка должна использоваться во всех сценариях:

- команда «Перевести»;
- команда «Озвучить»;
- индивидуальное озвучивание через `Ctrl+Space`;
- последовательное озвучивание «Повторить»;
- пакетная обработка;
- сохранение TXT и MP3.

Централизованное подключение необходимо, чтобы текст в окне перевода,
транскрипция IPA и произносимая TTS-фраза всегда совпадали.

## Алгоритм французской обработки

После обычного перевода обработчик должен:

1. Определить, является ли результат отдельным существительным или именной
   группой.
2. Определить главное существительное, его род и число.
3. Проверить наличие артикля или другого детерминатива.
4. Выбрать форму артикля согласно настройке пользователя.
5. Применить изменение только при достаточной уверенности.
6. В сомнительных случаях вернуть результат переводчика без изменений.

Для определённого артикля используются:

- `le` — единственное число, мужской род;
- `la` — единственное число, женский род;
- `l’` — перед гласной или немым `h`;
- `les` — множественное число.

Для неопределённого артикля используются:

- `un` — единственное число, мужской род;
- `une` — единственное число, женский род;
- `des` — множественное число.

## Случаи, которые нельзя изменять автоматически

Обработчик не должен добавлять артикль:

- к полноценным предложениям;
- к глаголам, наречиям и самостоятельным прилагательным;
- к именам собственным;
- к устойчивым выражениям, где артикль не требуется;
- к тексту, уже содержащему артикль или другой детерминатив;
- при неоднозначном определении части речи, рода или значения.

Необходимо учитывать не только `le`, `la`, `l’` и `les`, но и `un`, `une`,
`des`, `du`, `de la`, `au`, `aux`, `ce`, `cet`, `cette`, `ces`, притяжательные
и другие детерминативы. Повторный артикль добавляться не должен.

## Элизия и слова на h

Правило `l’` нельзя применять только по первой букве. Во французском есть:

- немое `h`: `l’homme`;
- придыхательное `h`: `le héros`.

Для таких случаев нужен лексический признак, хранящийся в словаре. Без этого
автоматическая обработка будет выдавать грамматически неверные формы.

## Морфологический анализ и словарь

Для определения частей речи, рода, числа и леммы можно использовать
французскую модель spaCy `fr_core_news_sm`. Она включает морфологический
анализатор, синтаксический анализ и лемматизацию. Однако статистическая модель
не гарантирует безошибочный результат, особенно для терминов и редких слов.

Поэтому рекомендуется гибридный подход:

1. пользовательский и встроенный словарь имеют высший приоритет;
2. затем применяется морфологическая модель;
3. при низкой уверенности текст остаётся без изменений.

Словарь предлагается хранить отдельно:

```text
language_data/French/lexicon.json
```

Пример структуры:

```json
{
  "table": {
    "gender": "feminine",
    "elision": false
  },
  "tableau": {
    "gender": "masculine",
    "elision": false
  },
  "école": {
    "gender": "feminine",
    "elision": true
  },
  "héros": {
    "gender": "masculine",
    "elision": false
  }
}
```

Официальная документация французских моделей spaCy:
<https://spacy.io/models/fr/>.

## Настройки пользователя

В окне Setting предлагается добавить параметр:

```text
Французские артикли:
    Автоматически
    Определённые
    Неопределённые
    Не добавлять
```

Предлагаемое поведение режимов:

- `Автоматически` — предложения остаются без изменений, а для уверенно
  распознанных слов выбирается учебная форма;
- `Определённые` — `le`, `la`, `l’`, `les`;
- `Неопределённые` — `un`, `une`, `des`;
- `Не добавлять` — исходное поведение переводчика.

Для изучения слов рекомендуется режим неопределённых артиклей. Например,
`une école` явно показывает женский род, тогда как форма `l’école` скрывает
различие рода.

## Озвучивание

В TTS необходимо передавать окончательно подготовленную французскую форму.
Если в окне перевода находится `une table`, то именно `une table` должна:

- использоваться при создании IPA;
- произноситься выбранным французским голосом;
- повторяться в последовательном режиме;
- сохраняться в MP3.

Текущий `edge-tts` поддерживает выбор голоса, скорость, громкость и высоту
тона. Произвольный SSML библиотека не поддерживает, поэтому грамматически
правильный текст должен быть сформирован до вызова TTS.

Официальная документация `edge-tts`:
<https://github.com/rany2/edge-tts/blob/master/README.md>.

## Возможное развитие переводчика

Текущий Google Translate через `deep-translator` можно сохранить как основной
переводчик на экспериментальном этапе. В дальнейшем возможна замена или
добавление провайдеров:

- Microsoft Azure Translator;
- DeepL API;
- контекстный LLM-переводчик со структурированным ответом.

Azure Dictionary Lookup возвращает варианты перевода, часть речи, обратные
переводы и в некоторых языках префикс-детерминатив. Однако словарная функция
ограничена поддерживаемыми направлениями и не должна считаться единственным
источником рода для прямого перевода с русского на французский.

Документация Azure Dictionary Lookup:
<https://learn.microsoft.com/en-us/rest/api/translator/translator/dictionary-lookup?view=rest-translator-v3.0>.

## Обязательные тестовые случаи

- мужской род: `tableau` → `le tableau` / `un tableau`;
- женский род: `table` → `la table` / `une table`;
- множественное число: `tables` → `les tables` / `des tables`;
- элизия: `école` → `l’école`;
- немое `h`: `homme` → `l’homme`;
- придыхательное `h`: `héros` → `le héros`;
- уже существующий артикль не дублируется;
- предложение не изменяется повторно;
- имя собственное остаётся без изменений;
- неизвестное или неоднозначное слово остаётся без изменений;
- текст окна перевода, IPA и TTS используют одну и ту же итоговую форму.

## Критерий готовности

Эксперимент считается успешным, если приложение уверенно обрабатывает
отдельные учебные слова и именные группы, не ухудшая обычный перевод
предложений, а результат на экране полностью совпадает с транскрипцией и
озвучиванием.
